# Devenv

[devenv](https://devenv.sh/) is a fast, declarative, reproducible, and
composable developer-environment tool built on top of Nix. Some projects in
this workspace use it instead of (or alongside) plain Nix flakes.

## Structure

```
devenv.nix          # Environment configuration (Nix module)
devenv.yaml         # Inputs: nixpkgs, devenv modules, imports
devenv.lock         # Pinned inputs (auto-generated by `devenv update`)
```

## Common commands

- `devenv init` — scaffold a new project (`devenv.nix`, `devenv.yaml`, `.gitignore`)
- `devenv shell` — enter the dev shell
- `devenv up` — start processes/services
- `devenv processes down` — stop background processes
- `devenv tasks run <task>` — run a defined task
- `devenv test` — build the environment and run all checks (use in CI)
- `devenv update` — update and pin inputs from `devenv.yaml` into `devenv.lock`
- `devenv inputs add <name> <url>` — add an input
- `devenv search <name>` — search packages in the nixpkgs input
- `devenv info` — print the environment summary
- `devenv build <attr>` — build an attribute from `devenv.nix`
- `devenv eval <attr>` — evaluate an attribute and return JSON
- `devenv repl` — inspect the environment in an interactive Nix REPL
- `devenv gc` — delete unused environments to save disk space
- `devenv lsp` — start the language server for `devenv.nix`

## Example

`devenv.nix`:

```nix
{ pkgs, ... }: {

  # https://devenv.sh/languages/
  languages = {
    # https://devenv.sh/languages/rust/
    rust = {
      enable = true;
    }; # ..languages.rust

    # https://devenv.sh/languages/nix/
    nix = {
      enable = true;

      lsp.enable = true;
    }; # ..languages.nix
  }; # ..languages

  # https://devenv.sh/services/
  services = {
    # ...
  }; # ..services

  packages = with pkgs; [
    just
  ]; # ..packages

  env = {
    "ENVIRONMENT" = "development";

    "JUST_INDENTATION" = "\t";
  }; # ..env

  git-hooks = {
    # https://devenv.sh/reference/options/#git-hookshooks
    hooks = {
      check-symlinks.enable = true;
      ripsecrets.enable = true;

      treefmt = {
        enable = true;
        # Configuration: ./.treefmt.toml
      }; # ..git-hooks.hooks.treefmt

      # Rust
      clippy = {
        enable = true;
        settings = {
          allFeatures = true;
          denyWarnings = true;
        };
      }; # ..git-hooks.hooks.clippy
    }; # ..git-hooks.hooks
  }; # ..git-hooks

  enterShell = ''
    echo $GREET
    jq --version
  '';

  # NOTE: Services are started prior to running
  enterTest = ''
    just test
  '';
}
```

`devenv.yaml`:

```yaml
inputs:
  nixpkgs:
    url: github:cachix/devenv-nixpkgs/rolling
  git-hooks:
    url: github:cachix/git-hooks.nix
    inputs:
      nixpkgs:
        follows: nixpkgs
```

## Best practices

- Pin all inputs via `devenv.lock` (run `devenv update`); commit the lockfile.
- Prefer the high-level modules (`languages.*`, `services.*`, `scripts.*`,
  `processes.*`) over hand-rolled `enterShell` code.
- Use `enterShell` only for simple hooks; use `tasks.*` for setup steps that
  need ordering or parallelism (`enterShell`/`enterTest` task hooks).
- Add custom project commands with `scripts.<name>.exec`; they get the same
  namespacing as system commands (`devenv` prefixes env names).
- Set `allowUnfree = true` in `devenv.yaml` only if the project needs unfree
  packages.
- For direnv integration, put `use devenv` in `.envrc` and run `direnv allow`.
- Run `devenv test` in CI to catch broken environments early.
- Format Nix files with `nixpkgs-fmt` (or `treefmt` if the project uses it).
- When a project mixes flakes and devenv, keep `devenv.nix` as the source of
  truth for the shell and let the flake shell just delegate to it
  (via `devenv.lib.mkShell` / flake-parts integration).
